# 走线主动避开节点 —— 设计稿

> 状态：**未实现**。记于 2026-09-30，等端口模型稳定之后做。

## 现在是怎么走的

`src/core/routing.js` 的 `orthoGeom(a, b, off, ka, kb)`：从两端锚点出发，
沿各自朝外的方向拉出去，中间用一条走廊连起来。走廊的偏移是**按边 id 哈希**算的
（`((hashId(e.id) % 7) - 3) * 9`）—— 目的是让平行线不完全重叠，
**它完全不看节点在哪**。

所以线会直接从别的节点身上穿过去。

## 要做成什么样

**尽可能避开节点**，避不开就穿过（不能为了避让把线绕得看不出关系）。

## 建议的做法：候选走廊打分

不要上 A\* / 可视图那套重家伙 —— 节点的排布通常是"一片一片"的，
用**少量候选走廊 + 打分**就能解决绝大多数情况，而且好调、好测。

```
1. 收集两端之间的障碍：所有节点/分组的盒子（排除这条边自己的两端）
2. 生成候选走廊：
   · 直连（当前行为）
   · 从两端朝外方向伸出去，走「上方 / 下方 / 左侧 / 右侧」四条外围通道
   · 每条通道再按若干偏移量细分（比如 -3,-2,-1,0,1,2,3 档）
3. 打分：穿过多少个盒子（权重最高）→ 拐弯数 → 总长度 → 走廊偏移（让平行线错开）
4. 取分最高的那条
```

**加分项**：
- 穿过盒子数 = 0 的方案优先于任何更短的方案
- 距离越近的盒子扣分越狠（从节点正中穿过比擦边更糟）
- 拐弯数要算进去，否则会出现为了避一个远节点而绕出一串折角

**必须有上限**：候选数 × 盒子数要可控。建议候选 ≤ 16 条，盒子 > 400 时直接退回直连
（大文档里逐条边做避让会拖慢整体重绘）。

## 几个坑

| 坑 | 说明 |
|---|---|
| **性能** | `edgeGeomFor` 在每次 `draw()` 里对**每条边**调用。加避让之后必须缓存：拓扑/位置没变就别重算 |
| **稳定性** | 节点动一下走廊就跳变会很难受。分数接近时应该倾向**保持上一次的选择**。可以按边 id 缓存上一次的走廊 |
| **不能碰端点** | 端点是钉死的，避让只能改**中间那段**，两端那段必须保持朝外方向（否则线会从端点上斜着飞出去） |
| **拐点（waypoints）优先** | 用户手动拖过拐点的边，一律按拐点走，不做避让 —— 那是他明确指定的 |
| **分组** | 分组框会套住节点。避让时把分组框当障碍会绕得离谱；建议**只当节点是障碍**，分组框不参与 |
| **曲线走线** | `route:'curve'` 的贝塞尔本来就会绕，先不处理；避让只做 `ortho` |

## 该有的断言

- 两个节点之间横着一个节点 → 走线不穿过它（采样路径上的点，逐个判 `inBox`）
- 没有任何障碍时 → 走线**和现在一模一样**（不能因为加了避让把简单情况弄复杂）
- 障碍挪走之后 → 线回到直连
- 端点位置没被避让影响（两端仍然精确落在端点上）
- 有拐点的边不做避让
- 大文档（几百节点）时 `draw()` 的耗时不能爆（至少要有退回直连的上限）

## 已修：线从**自己**身上穿过去（2026-09-30 修好）

**修法**（和下面「试过的改法」不同 —— 这次没有动 `avoidBoxes` 的契约）：

1. 把两端的盒子**单独**算一次穿盒数，作为**次级**权重：
   穿别人 ×100000，穿自己 ×10000，再比偏移。
2. 补两条「绕开自己」的候选：出桩 → 沿桩口竖直到两个盒子**之外** → 再横过去 → 入桩。
3. 提前退出的条件从 `cross===0 && d===0` 收紧成 `cross===0 && self===0 && d===0`。

**关键坑**：`segHitsBox` 是 **AABB 重叠判定**，不是真的线段相交 ——
出桩那一段本来就从节点边上出发，必然和节点盒子重叠，
所以直接数会得到「每个候选都在穿自己」，打分完全区分不出来。
必须用 `pathCrossCountInner`，**跳过两端各一段桩**（段 i 覆盖 `pts[i-1]→pts[i]`，
所以 i 从 2 到 `pts.length-2`）。

**为什么这次没把 `E03c` / `Y07` 弄红**：`avoidBoxes` 的契约一个字没改，
只是加了次级权重和额外候选。上次直接改契约，数据结构变了之后
就分不清是「结构」还是「几何」出的问题。

## 历史记录：当初的两次失败尝试

### 现象

端点朝外方向**背着目标**时，线是「先向外出桩 → 再折回来」，**折回来那一段穿过自己**。

### 原因

`avoidBoxes(e.s, e.t)` 是**排除两端**的 —— 这是为了让「出桩那一小段」
（本来就从节点边上出发）不被误判成「撞自己」。
副作用就是：「折回来压在自己身上」这种情况**永远发现不了**。

### 试过的改法（**没成功，已回退**）

把两端盒子也纳入评分，并用 `isEnd` 标记跳过出桩 / 入桩段：

```js
const from = isEnd ? 2 : 1;              // 段 i 覆盖 pts[i-1]→pts[i]
const to   = isEnd ? pts.length - 1 : pts.length;
```

结果：`E03c`（导出左上角应为空）和 `Y07`（框选整个分组）**红了**。

### 关键教训：两个实验都做错了

1. 第一次为了「先排除路由几何的影响」，把障碍传成 `[]` ——
   **但新代码是无条件 `boxes.push(两端)` 的**，`boxes` 长度是 2 不是 0，
   **避让根本没被关掉**。于是得出了「跟几何无关」的**错误结论**，白绕了一圈。
2. `avoidBoxes` 的契约一改，就分不清是「数据结构变了」还是「几何变了」。

### 下一步该怎么做

1. **先单独跑 `E03` 和 `Y07`**，确认它们在干净 HEAD 上是绿的（已确认：跑两遍都绿）
2. **`Y07` 是框选，和走线毫无关系** —— 它跟着翻说明有一处**我不知道的耦合**。
   这是首要疑点，必须先搞清它为什么会受影响，再动这个 bug
3. 改的时候**一次只动一处、跑一次**。这次我一次动了「障碍表结构 + 穿盒子计数 + 边界」，
   红了之后没法二分

### 可以试的更窄的做法

- 只在 `backA || backB`（端点朝外方向背着目标）时才启用自穿检查
  —— 试过了，**还是红**，说明 classic 示例里本来就有 `back` 的边
- 或者：不动障碍评分，改成**在 `buildPts` 里就把出桩方向翻正**
  （端点背着目标时，桩子朝里打）—— 这更接近问题本质，值得先试
